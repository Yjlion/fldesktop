# Contributing to fldesktop

## Building

```sh
cmake -B build -G Ninja
cmake --build build
ctest --test-dir build --output-on-failure
tools/run-dev.sh            # a nested fl-wm session from the build tree
```

The dependencies for Arch Linux and Debian are listed in `.github/workflows/ci.yml`. Programs whose
libraries are missing are left out with a warning; `-DFLD_BUILD_<APP>=OFF` leaves one out on purpose.

Build options for checking your work:

| Option | What it does |
|--------|--------------|
| `-DFLD_SANITIZE=address,undefined` | AddressSanitizer and UBSan (CI runs ctest this way) |
| `-DFLD_FUZZ=ON` (with `CC=clang CXX=clang++`) | libFuzzer targets in `build/bin/fuzz_*` |
| `-DFLD_HARDENING=OFF` | without `_FORTIFY_SOURCE`, stack protector, RELRO and PIE (on by default) |

Fuzzing a parser, for example the INI reader:

```sh
CC=clang CXX=clang++ cmake -B build-fuzz -G Ninja -DFLD_FUZZ=ON -DFLD_SANITIZE=address,undefined
cmake --build build-fuzz --target fuzz_ini
./build-fuzz/bin/fuzz_ini -max_total_time=60 tests/fuzz/corpus/ini
```

Without `FLD_FUZZ`, ctest still replays each seed corpus in `tests/fuzz/corpus/` (`fuzz-*` tests).
When a fuzzer finds a crash, fix it and add the input to the corpus.

## Code

- C++17 for the apps, the shell and the libraries; C11 for fl-wm (`compositor/`).
- `.clang-format` describes the style. Format only the lines you change (`git clang-format`), not whole files.
- Shared code goes into `common/libfld` (FLTK helpers, INI, JSON, desktop entries, processes) or one of
  the `common/*` libraries. Logic that can be tested without a display goes into a small static library
  next to the app (`fl-docs-util`, `fl-remote-util`, ...) and gets a test in `tests/`.
- Run programs with `fld::spawn()` / `fld::run_capture()` (argv, no shell). Do not build shell command
  strings (`system()`, `popen()`, `sh -c`) from data.
- Anything that runs as root is a pkexec helper with a polkit action, validates every argument and reads
  user files with `fld::read_user_file()`. See `doc/THREAT-MODEL.md`.
- User-visible text is plain English, short, and in sentence case.

## Tests

`tests/CMakeLists.txt` registers unit tests (`test_*.cpp`) and smoke tests (`*-smoke.sh`, which start a
headless fl-wm). A test that cannot run in the current environment exits with 77 (skipped).
fl-settings' search index is generated by `tools/settings-index.py`; ctest checks that it is current.

## Commits and pull requests

- One topic per pull request, against `main`. CI (Arch and Debian, plus the sanitizer leg) must pass.
- Describe what changed for the user, and how you tested it.
- Release tags (`v*`) set the version and publish packages; only maintainers push them.

## Reporting security problems

Please use GitHub's private security advisories, not a public issue.
