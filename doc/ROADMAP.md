# fldesktop roadmap

A list of improvements and features for later work, based on an analysis of the tree as of v0.1.4
(about 118k lines of C/C++: the fl-wm compositor, the shell, libfld and 38 apps).
Nothing here is scheduled. Each item is meant to be picked up on its own.

### 1. Foundations (do first)
1. **Internationalization.** No source file uses gettext and there is no `po/` directory, even though Settings >
   Language & Region sets `LANG`.
   - Add `_()` and `N_()` through `libfld`, a `po/` tree with CMake `msgfmt` rules, and a `.pot` check in CI.
   - Check RTL and long-string layouts.
2. **CI hardening.** There are no ASan/UBSan, coverage, clang-tidy or fuzzing jobs.
   - Add an ASan/UBSan matrix leg that runs ctest.
   - Add libFuzzer targets for the parsers that read untrusted input: `libfld/ini.cpp`, `json.cpp`,
     `desktop_entry.cpp`, `mime.cpp`, the `fl-docs` Markdown/EPUB/ODT readers, M3U/PLS, `.ovpn`/wg-quick import,
     the fl-remote RFB client, and `compositor/config.c`.
   - Build with `_FORTIFY_SOURCE=3`, stack protector, RELRO and PIE.
3. **Large source files.** `apps/fl-files/main.cpp` has 4.3k lines, `fl-web/main.cpp` 2.6k, `fl-edit/main.cpp`
   1.9k, `fl-snip/main.cpp` 1.6k and `compositor/view.c` 1.5k. Split each into view, model and actions units,
   following the `fl-settings/pages/` pattern.
4. **Security review of privileged paths.** These need a review and a threat-model document in `doc/`:
   - the pkexec helpers (fl-disks `helper.cpp`, fl-settings `helper.cpp` and `users_helper.cpp`);
   - the compositor's trust check for shell clients, which goes by app id and executable path;
   - the lock-screen exit-status protocol;
   - the `popen()` call that builds a shell string in `fl-sysinfo/sysinfo.cpp:627`.

### 2. fl-settings: improvements and what to split out
Current state: 26 compiled-in pages in four categories, 7.9k lines in all.
- Each page is one file, registered in CMake with `fld_settings_page()`.
- The search index is generated by `tools/settings-index.py` and checked by ctest.
- Network, Printers, Bluetooth, Firewall and Sound are thin wrappers (31–55 lines) around the shared `*-ui`
  libraries of the standalone apps. This pattern works well; keep it.

**Reorganize the pages: the window settings are scattered today.**
- `focus_follows_mouse` and `workspaces` are on the *Mouse* page.
- Snapping, `drag_modifier` and hot corners are on the *Shortcuts* page.
- Title bars are on the *Appearance* page.
- `shadows`, `title_height`, `renderer` and `xwayland` (wm.ini) have no UI at all.

Changes:
- New **Windows & Workspaces** page: focus mode, number of workspaces, snapping and snap assist, the drag
  modifier, hot corners, shadows, the title-bar height, and later window rules and per-output workspaces.
  Shortcuts then holds key bindings only.
- New **Startup Applications** page, using `~/.config/autostart`. `shell/autostart.cpp` already reads these
  entries; today only the Accessibility page (Orca) and the Keyboard page (input methods) write them.
- Split **Wallpaper / Background** out of Appearance (385 lines: accent, style, wallpaper gallery, fonts, title bars).
- Give **Night Light** its own page or section. It lives inside Displays today. Replace the
  `sh -c "pgrep … || exec fl-nightlight"` call in `displays.cpp` with a helper in `libfld`.
- Merge **Proxy** into Network as a tab. Consider merging **Drives** (71 lines) into a "Removable Media" section
  of Power or Devices.
- New **Tablet / Pen** page. The compositor already supports tablet-v2.
- New **Advanced** page: the renderer and Xwayland switches (needs a restart).

**Split out of the source files**
- `pages/users.cpp` (802 lines) holds the new-user dialog, the password strength box, the picture picker, the
  fingerprint enrolment and the page itself.
  - Move the dialogs into `users_dialogs.cpp`.
  - Move the picture picker into `libfld/avatar.cpp` so fl-welcome and the greeter can reuse it.
  - Move fingerprint enrolment into `common/fprint` UI code, next to the backend.
- `pages/displays.cpp` (596 lines): the wlr-output-management client and the layout canvas become their own
  unit, `displays_model.cpp`.
- `pages/shortcuts.cpp` (496 lines): move the hot-corners and app-shortcut dialogs into their own files.

**Split out as standalone apps**
- **fl-displays.** It only needs wlr-output-management, so it would also work on sway, labwc and Hyprland.
  It would be a library and a page, the same as fl-network.
- **Users and Login Screen** as an admin tool (`fl-users`), for systems where fl-settings is not used.

**General UX**
- Add **Reset to defaults** on every page. Only Shortcuts has it today.
- Make apply behavior consistent. Most pages apply at once, Displays reverts after a timeout, and Login Screen
  saves through polkit. Show the same status bar and messages on every page.
- **Consolidate the root helpers.** `helper.cpp`, `users_helper.cpp` and the greeter config writer could become
  one polkit helper with a strict action allowlist, plus unit tests for argument validation.
- **Export/import settings**: back up and restore `~/.config/fldesktop`.
- A **command-line and D-Bus interface** (`fl-settings --get/--set section.key`) for scripts and tests.
- Load the external "More" settings programs lazily, and show a hint when a page is left out at build time
  because a library is missing.

### 3. Compositor (fl-wm)
- **Window rules** (`[rules]` in wm.ini), matched by app id or title: workspace, output, size, floating,
  always-on-top, opacity.
- **Optional tiling layout** for each workspace (master/stack or columns).
- **Animations** (open, close, minimize, workspace slide), with a "reduce motion" switch in Accessibility.
- **Workspaces for each output.** Workspaces are global today.
- Add `xdg-toplevel-drag-v1`, and finish the color-management/HDR path with a UI in Displays.
- **Session save and restore** of apps and window positions.
- Rounded corners as an option.

### 4. Shell & session
- **Layer-shell through FLTK.** Add a `libfld` shim that uses wlr-layer-shell through FLTK's Wayland handle, so the
  panel and desktop no longer have to be recognized by name and executable path, and also work under other compositors.
  *Blocked on FLTK (checked against 1.4.5 and master, November 2026):* `Fl_Wayland_Window_Driver::makeWindow()`
  gives every top-level window an xdg_surface as soon as it is shown, and the public API (`FL/wayland.H`) has no
  way to give it another role. A shim would have to intercept libwayland requests inside FLTK, which is too fragile
  to ship. The way forward is an FLTK change: a hook (or a window type) that lets the program assign the surface
  role itself. Propose it upstream, then add the shim here.
- A **quick settings** popup with Wi-Fi, Bluetooth, DND, night light, power mode and volume.
- Notifications grouped by app, with inline reply.
- Launcher providers: a calculator, unit conversion, file search and commands.
- A **plugin API for panel applets**, as a `.so` ABI or over D-Bus. Today the applets are compiled into fl-panel
  (`shell/panel_*.cpp`).

### 5. New apps (near term)
- **fl-diskusage**: a treemap view, next to fl-disks and fl-files.
- **fl-recorder**: an audio recorder on GStreamer/PipeWire, which are already used.
- **Color picker and screen ruler** in fl-snip, reusing its magnifier.

### 6. Per-app improvements
- **fl-files:** previews on Space (quick look with fl-view, fl-docs or fl-media-player), git emblems, a
  duplicate finder, a search index.
- **fl-edit:** a split editor, a folder sidebar, git gutter marks, a terminal pane (reusing fl-term's widget),
  and LSP rename, code actions and formatting.
- **fl-term:** broadcast input to panes, session restore, OSC 8 and OSC 52 (check first whether they exist),
  Sixel or kitty images.
- **fl-web:** password CSV import, per-site zoom memory, userscripts.
- **fl-media-player:** an equalizer, gapless playback, ReplayGain, chapters.
- **fl-docs:** annotations and highlights saved to the PDF, form filling.
- **fl-paint:** layered save (ORA), and pen pressure from the existing tablet-v2 support.

### 7. Engineering & project hygiene
- `doc/ARCHITECTURE.md` (process map, D-Bus names, trust model), CONTRIBUTING, `.clang-format`, issue templates.
- CI: cache the dependency installs, add a Fedora or Ubuntu leg (wlroots 0.19), run `reuse lint`, and track
  startup time and memory (`tools/memstat.sh`).
- Packaging: a Fedora spec, a Nix flake, an Alpine APKBUILD.
- Local crash capture, with a "report" button in fl-logs that fills an issue template.

### 8. Later (needs research or large infrastructure)
- **fl-calendar + contacts (CalDAV/ICS).** Needs an online-accounts and auth layer (OAuth, credentials in
  the Secret Service) first. Design that layer separately before starting.
- **fl-backup (rsync/restic, Btrfs/Snapper snapshots).** Needs research on which backends to support, how to
  schedule and restore, and how to handle root and user data.
- **fl-mail (IMAP/SMTP).** A very large app (MIME, HTML rendering, offline store, auth). It depends on the
  accounts layer above.
- Online Accounts settings page, which the three apps above would share.

### 9. Suggested order
1. i18n, sanitizers and fuzzing in CI.
2. The fl-settings reorganization (Windows & Workspaces, Startup Applications, splitting the large files,
   one root helper) and the security review.
3. Window rules, per-output workspaces and the layer-shell shim.
4. The near-term apps, then the per-app improvements.
5. The "Later" items, once the accounts layer and the backup research are done.
